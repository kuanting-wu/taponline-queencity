What theming doesn't do

Custom theme is a module that's off by default and is switched on per gym; without it the Appearance page isn't available. It only themes the member app, its loading screen and its Home Screen icon. The staff app and the owner console always keep the platform look, so they're shown unchanged below. Status colors (warning, success, danger), grouped-list layout and wording stay the same. Dark mode keeps a black ground with a lifted brand color.

03Staff app

Staff app stays neutral

All staff app screens · and every owner console page

The product deliberately keeps staff screens on the platform look, so coaches and owners who work across several gyms always see the same interface. This page doesn't pretend otherwise: there's no custom version of these screens.

04Question · a fully custom member app

Does the builder still matter?

Suppose QCGC wanted more than a theme: a member app designed from scratch for the club. Would the owner's Appearance builder still do anything, or would it become obsolete? Short answer: it keeps working as long as the custom app is built to read the builder's values. If the brand is hardcoded instead, the builder stops affecting what members see.

Step 1 · Owner

Saves values

  • Appearance stores a set of theme values per gym. They are settings, not code
  • Brand and secondary color, button shape, font, page background and dim
  • Logo, member card image and text color, Home Screen icon, icon background and short name
  • Loading motion, member colors (gym or belt), class card style
  • Changing them needs the Custom theme module
Step 2 · Backend

Hands them out

  • The signed-in member session includes the gym's theme values
  • A public branding lookup gives the name, short name, logo, icon, brand color and loading motion for the sign-in, loading and install screens before sign-in
  • Any front end on the same backend receives exactly the same values
Step 3 · Member app

Applies them

  • Values become a few style variables on the app's outer frame: brand color and its tints, corner radius, font, background
  • The stock components read those variables
  • The member card, loading screen and install icon read the logo, card image, icon and short name directly
  • Belt mode swaps the brand color for the member's own belt color
What it isn't

A skin, not a layout

  • Theme values restyle the existing components. They don't change layout, navigation, which screens exist or any wording
  • Class page block order is a separate setting (Settings › Class page)
  • The class card style value is saved but not yet used by member screens
Builder settingStock member app (today)Custom member app on the same backend
Brand color, tints, button shape, font, backgroundApplied automatically to every screenStill works if the custom styles use these values as variables. Lost wherever the design hardcodes its own
Logo, member card image + text colorUsed by the sign-in screen, card and loading screenStill delivered. The custom card and screens have to place them
Home Screen icon, short name, loading motionBuilt into the install manifest and loaderStill delivered by the public branding lookup. The custom app must keep its own manifest and loader reading them
Member colors · beltRecolors actions to the member's beltNeeds the custom app to repeat the rule: belt and Custom theme modules on, and the member's current belt known
Contrast grade, templatesGuide the owner's choiceStill useful, because they check the color itself and not the layout
Live preview in the builderShows the stock member appWould no longer match: it draws the stock screens, not the custom ones
Everything that isn't appearanceUnaffected either way: bookings, credits, payments, waivers, check-in rules, module switches and class page layout live in the backend, not in the theme
What we'd recommend

Keep the Appearance builder as the layer the owner can edit, and build the custom QCGC design on top of it. The custom app keeps its signature layout and type, but reads brand color, background, radius, font, logo, card image, icon, short name and loading motion from the gym's theme values instead of hardcoding them. Keep the Custom theme module switched on, so staff can change a card photo, a seasonal background or the logo without a developer. Two follow-ups make this complete: update the builder's preview to draw the custom screens (or label it as approximate), and keep the install icon and loader reading the same values. The staff app and owner console aren't themed today, so a custom member app doesn't change them.

A product walkthrough of TapOnline prepared by Quentin Wu for Queen City Grappling Club. It is not affiliated with or endorsed by QCGC. QCGC's name is used only to personalize this proposal.
